# PlayFit Vision

Учебное веб-приложение: модель **MediaPipe Pose Landmarker** распознаёт ключевые точки тела, а геометрические правила определяют фазы упражнения, считают повторения и дают простые подсказки. Камера и видео обрабатываются в браузере; платных AI API и сервера обработки нет.

## Возможности

- Камера в реальном времени, наложение скелета на Canvas.
- Каталог из семи учебных программ: поиск, фильтры, настройка плана на сессию, последовательность упражнений с подходами и отдыхом, общий итог с разбором каждого шага. Камера или синтетическое демо; видеозаписи доступны в одиночной тренировке. [Контракты и ограничения программ](docs/platform/programs.md).
- Подготовка камеры с примером съёмки сбоку, проверкой точек и устойчивой исходной позиции. Для приседаний без веса ракурс проверяется отдельной эвристикой; при неопределённости можно подтвердить профиль вручную по примеру.
- Приседания и отжимания: подсчёт циклов через конечный автомат, сглаживание и переходы по времени, подтверждение замечаний достаточным наблюдением.
- Подсказки о глубине, наклоне корпуса, неполном выпрямлении и положении тела (в зависимости от упражнения).
- Голосовые подсказки об ошибках на русском через Web Speech API. Звук можно включать и выключать в панели тренировки; выбор сохраняется в браузере. Доступность и произношение зависят от установленных русских голосов.
- Итог: полные повторы, неполные и неоценённые попытки, замечания и разбор проверок с причинами нехватки данных. Общий процент техники не используется.
- Собственная цель: подходы, полные повторы и отдых. Пауза, отдых и следующий подход не учитывают движения; продолжение требует новой устойчивой исходной позиции. Значения нагрузки автоматически не назначаются.
- Гостевая история в браузере и отдельная серверная история каждого аккаунта: детали подходов, сопоставимые наблюдения со знаменателями, удаление гостевых записей, скрытие серверных записей с подтверждением и JSON-экспорт. Демо исключено из личного прогресса; камера и записи разделены.
- Схема движения на главной с ручным переключением описаний возможностей; быстрый вход в демо, адаптивные экраны тренировки и истории. Подробные параметры и проверки раскрываются по запросу.
- **Демо без камеры** на искусственно заданных точках тела для проверки счётчика и интерфейса. Демо честно помечено как симуляция и **не демонстрирует распознавание моделью**.
- **Видеофайл** пользователя: тот же путь MediaPipe → анализатор, что и при работе камеры. Файл используется локально и не загружается на сервер.
- Модель и WebAssembly поставляются в `public/`; их не нужно загружать со стороннего CDN при открытии приложения.

- Регистрация и вход по логину/паролю, сохраняющаяся сессия, профиль с локальным аватаром и реальными показателями. Явный импорт прежней гостевой истории с предварительным итогом и без дубликатов.
- Конструктор личных программ: создание, перестановка шагов, редактирование, копирование каталожного или своего шаблона и избранное в аккаунте. Правка и удаление программы сохраняют прежние итоги и снимки начатых запусков. [Права, версии и API](docs/platform/builder.md).
- Персональный `/overview` после входа: уровень, XP, активность за 7 дней, последние результаты, избранное и восемь достижений. Полностью выполненное новое камерное задание аккаунта даёт 20 XP один раз; максимум 60 XP за тренировки в день по Europe/Kyiv, новый уровень каждые 100 XP. Значки без бонусных XP. Архивирование не отменяет награды и активность. [Правила, API и контракт событий](docs/platform/game-rules.md).

Этап 7 добавляет `/competitions/duels`: создание из каталога, принятие по коду, одна камерная сессия на участника, черновик записанных шагов, окончательная отправка, сопоставимые баллы, ничья/победа/истечение и однократные бонусы через общий журнал. Незаписанные кадры после reload не восстанавливаются. В обзоре — приглашения и ожидания, в профиле — значок первой дуэли. [Автомат, API и события для будущего рейтинга](docs/platform/duels.md).

## Запуск

Этап 6 добавляет `/competitions`: учебные испытания, явное участие, связанные камерные запуски, сохранённый прогресс, отдельные фиксированные XP и соревновательные очки. Активные задания и седьмое достижение за первое испытание видны в обзоре/профиле. [Сроки, допустимые источники, снимки и API](docs/platform/challenges.md).

Для актуальных относительно дня запуска учебных испытаний выполни **отдельно** `npm run db:seed:challenges`. Команда повторяема, создаёт три задания текущей недели и один анонс следующей по Europe/Kyiv; сохраняет старые участия/условия/результаты и не создаёт вымышленных участников. При обычном перезапуске приложения сроки не сдвигаются. Начисление бонуса испытания расширяет политику XP: предел 60 XP в день применяется к тренировкам, бонусы испытаний выдаются сверх него один раз. [Размеры и пределы наград](docs/platform/game-rules.md).

Нужен Node.js 22.12+ (ветка 22 LTS) или 24 LTS. На Windows проверен Node.js 22.13.1 и npm 10.9.2. Docker, Python и облачные сервисы не нужны.

```bash
npm install
npm run db:migrate
npm run dev
```

Откройте адрес, который покажет Vite (обычно `http://127.0.0.1:5173`; если порт занят — следующий свободный). Команда запускает клиент и API вместе; Ctrl+C останавливает оба процесса и их дочерние процессы. API слушает только `127.0.0.1:3001`, проверка — `/api/health` через адрес клиента или `http://127.0.0.1:3001/api/health`. При запуске API также применяет недостающие миграции.

База создаётся в `data/playfit.sqlite`. Команда миграций повторяема и не очищает данные. Настройки необязательны: скопируйте `.env.example` в `.env`, задайте `API_PORT` и `DATABASE_PATH`, затем перезапустите `npm run dev`. Относительный путь БД считается от корня проекта; `.env`, БД и её WAL/SHM исключены из Git. Нестандартную БД храните вне репозитория либо добавьте точные правила исключения для неё и служебных файлов.

Страницы: `/`, `/training?exercise=squat&mode=camera`, `/history`, `/history/:id`, `/login`, `/register`, `/profile`; неизвестный адрес показывает «Страница не найдена». Упражнение (`squat/pushup`) и источник (`camera/video/demo`) сохраняются в URL при переходах и обновлении. Форму цели, незавершённую тренировку и выбранный локальный файл после обновления нужно задать заново. Гостевая история хранится в браузере. История вошедшего пользователя хранится отдельно в локальной SQLite; видео и поток точек не отправляются на сервер. Вход сохраняется после reload, выход отзывает сессию. Импорт гостевых записей выполняется явно из истории аккаунта. [Аккаунты, API и источники](docs/platform/accounts.md). [Реализованная архитектура и контракты](docs/platform/architecture.md).

Для камеры браузер запросит разрешение; в production необходим HTTPS. Если браузер отказал в разрешении, измените его в настройках сайта и нажмите кнопку запуска ещё раз.

Проверка:

```bash
npm test
npm run check:server
npm run test:server
npm run build
```

`npm run build` отдельно собирает сервер в `.server-build/`, проверяет TypeScript клиента и собирает Vite в `dist/`. Только сервер: `npm run build:server`, затем `npm run start:server`. Для проверки собранного клиента оставьте API запущенным в одном терминале и выполните `npm run preview` в другом; preview также проксирует `/api`. В PowerShell при ограничении запуска `npm.ps1` используйте `npm.cmd` вместо `npm`.

## Как работает AI

```text
Камера / локальный видеофайл
    ↓
MediaPipe Pose Landmarker (в браузере)
    ↓
Координаты и видимость суставов
    ↓
Угол и геометрия + сглаживание
    ↓
Конечный автомат упражнения
    ↓
Повторы, подсказки, статистика
```

Полный повтор засчитывается после наблюдаемого движения от верхней точки через нижнюю и обратно, если обязательные проверки не имеют пропусков данных. Замечания о наклоне корпуса или линии тела сохраняются отдельно от исхода движения. Неглубокие движения и незавершённое выпрямление попадают в отчёт как неполные попытки. Если обязательные точки ненадёжны, попытка получает исход «недостаточно данных»; отсутствие замечаний не превращается в положительную оценку.

Перед первым движением удерживайте исходную верхнюю позицию около половины секунды. Подготовка не добавляет повторов. При потере наблюдения угол и техническая подсказка скрываются, озвучивание прекращается. Разрыв более 700 мс разделяет движение; после него нужна новая устойчивая исходная позиция. Видеофайл запускается после подготовки модели, проигрывается один раз и автоматически завершает анализ с сохранением незаконченной попытки. Темп измеряется по времени записи. Перемотка прерывает попытку; повторный запуск с экрана результата начинает анализ с нуля. Портретные и широкие записи отображаются без растяжения, скелет учитывает поля изображения. Камера, видео и демо используют один анализатор.

Ошибки распознавания и неверный ракурс влияют на результат. Правила приблизительны и не измеряют безопасность. Основной сценарий — приседания без веса строго сбоку: камера примерно на уровне таза, плечо, таз, колено и лодыжка ближней стороны в кадре весь подход. Дальняя сторона может быть закрыта; при неопределённости эвристики сверьтесь с примером. Для отжиманий также расположите камеру сбоку. Контракты результатов описаны в [docs/analysis-contract.md](docs/analysis-contract.md), параметры и ограничения — в [docs/camera-and-squat.md](docs/camera-and-squat.md).

Текущая подсказка показывает одно актуальное замечание с текстовой меткой связанного сегмента. Причина потери данных имеет приоритет над техникой. Предыдущая попытка разбирается отдельно: исход, причина отказа, доступный угол/длительность и результаты критериев. Итоги предлагают одну следующую задачу; при малом количестве данных — настройку съёмки. Голос имеет ограничение частоты и отменяется при смене сообщения/потере позы/завершении; текст работает и без него. [Политика подсказок, ограничения и ручная проверка](docs/actionable-feedback.md).

Перед запуском заполните собственную цель. Подход завершается при достижении числа полных оценённых циклов либо кнопкой; замечания не вычитают полный цикл, неполные и неоценённые попытки не повышают счёт цели. Во время паузы незаконченная попытка фиксируется как неоценённая с причиной паузы. Отдых заканчивается по таймеру, следующий подход запускается явно. Файл при паузе/отдыхе останавливается и продолжается с того же места; конец записи завершает всю сессию. [Контракты сессии, хранения, сравнения и ручная проверка](docs/training-history.md).

### Структура

- `src/pose/` — модель, контроль качества точек, геометрия, рисование и демо-точки.
- `src/exercises/` — типы и анализатор упражнений, без зависимости от React.
- `src/hooks/useTraining.ts` — запуск источника видео, цикл анализа, таймер и освобождение ресурсов.
- `src/components/TrainingView.tsx` — экран тренировки и результатов.
- `src/training/` — автомат сессии, схема локальной истории и показатели сопоставимых наблюдений.
- `src/components/HistoryView.tsx` — история, детали, экспорт и подтверждение удаления.
- `src/App.tsx` — общий layout и маршруты существующих экранов; `src/routing/` — проверка выбора из URL.
- `server/` — Fastify, конфигурация, SQLite и нумерованные SQL-миграции; browser-only анализатор от сервера отделён.
- `docs/platform/architecture.md` — реализованные API/БД, команды и границы следующих этапов.

Новые упражнения можно добавлять отдельным анализатором, сохранив общий интерфейс `ExerciseAnalyzer`.

## Статическая публикация клиента

Текущий полный сценарий запуска — локальные Vite + Fastify + SQLite. Папка `dist/` содержит только клиент: статический хостинг не запускает API и не хранит SQLite. Для прямых URL на статическом хостинге нужен fallback на `index.html` (кроме `/validation.html` и ресурсов). Отдельное размещение API и настройка маршрута `/api` не входят в этап 1. Камера на внешнем адресе требует HTTPS.

Модель `pose_landmarker_lite.task` и wasm-файлы лежат в `public/`, поэтому публикуйте всю папку проекта, включая `public`. При первом запуске модель загружается в память устройства; GPU используется при доступности, иначе автоматически выбирается CPU.

## Ограничения

- Детектор работает синхронно; кадры ограничены примерно 12 FPS для снижения нагрузки. На слабых устройствах возможны краткие задержки интерфейса. Выделенный worker — возможное улучшение следующей версии.
- Каталог и детали программ доступны по `/programs` и `/programs/:id`. План фиксируется на запуск. Для дуэли восстанавливаются записанные шаги; у обычной программы незавершённый запуск после обновления не восстанавливается. Для сохранения досрочного итога нажми «Прервать программу» перед уходом. Гостевые программы хранятся отдельно от v1; их импорт в аккаунт пока не реализован.
- Личные программы — `/my-programs`, создание — `/programs/new`, редактор — `/programs/:id/edit`, избранное — `/favorites`. Нужен вход. Черновик формы сохраняется в этой вкладке, если доступен sessionStorage; он не заменяет сохранение программы. Удаление архивирует шаблон, восстановление через UI пока недоступно.
- Правила техники приблизительны, основаны на 2D проекции тела, и не заменяют профессионального тренера или врача.
- Одновременно анализируется один человек. Для стабильного результата нужны хорошее освещение, всё тело в кадре и удобный ракурс.
- Демо использует синтетические точки. Для проверки реального ML без камеры выберите «Видеофайл» и откройте запись упражнения.
- Автотесты проверяют счёт на искусственных движениях при интервалах 33–200 мс и циклах 1.8–8 с. Это не измерение точности MediaPipe, ракурса или замечаний на людях: реальные записи ещё предстоит проверить.
- Завершённые гостевые сессии сохраняются в localStorage этого браузера, результаты аккаунта — в локальной серверной SQLite. Незавершённая или ещё не подтверждённая сервером обычная тренировка после reload не восстанавливается; в дуэлях доступны подтверждённые записанные шаги, но не текущие кадры/подходы. Видео и координатный поток не сохраняются. При запрете/переполнении хранилища результат можно экспортировать с экрана итогов; повреждённая история не заменяется автоматически. Очистка данных браузера удалит гостевую историю; серверные записи аккаунта сохранятся. Явный импорт прежней localStorage-истории доступен в аккаунте; загрузка JSON-файла пока не реализована. Демо, видео и импорт не начисляют игровых наград.
- Если браузер не поддерживает синтез речи, текстовые подсказки продолжают работать, а переключатель звука недоступен.

Модель взята из [официального семейства MediaPipe Pose Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker/web_js). Подробности API: [руководство MediaPipe для Web](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker/web_js).

## Локальная валидация видео

Отдельная страница `/validation.html` прогоняет разрешённый локальный файл через MediaPipe и анализатор, экспортирует таймкоды/версии и сравнивает результат с независимой разметкой. [Запуск и метрики](docs/validation/README.md), [формат набора](docs/validation/format.md), [памятка разметчику](docs/validation/annotator.md), [текущий отчёт](docs/validation/REPORT.md). Частные материалы и выгрузки храните в игнорируемой `validation-private/`, не в `public/`.

Инструменты и синтетические проверки готовы; реальные записи и эталонная разметка пока отсутствуют. Качество на людях и предварительные правила техники не валидированы.
