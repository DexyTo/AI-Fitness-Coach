# Формат набора v1

Набор — каталог в `validation-private/` с исходными локальными видео, одним `*.annotation.json` на клип, `*.run.json`, производными `*.report.json` и локальным индексом. Одна аннотация описывает непрерывный ролик целиком, начиная с 0. Для нескольких упражнений/ракурсов заранее создайте отдельные клипы и пересчитайте хеши. Не изменяйте контейнер после разметки. Формат и runtime-проверки заданы `src/validation/{types,schema}.ts`; полный машинно читаемый пример — [synthetic.annotation.json](examples/synthetic.annotation.json). Это искусственный пример, не шаблон разрешения на съёмку.

| Поле | Обязательное содержание |
| --- | --- |
| `schemaVersion` | `1` |
| `material` | `real` для реальных записей, `synthetic` только для искусственных примеров |
| `clipId` | Анонимный уникальный slug, буквы/цифры/`_`/`-`; без имени или пути |
| `participantGroupId` | Случайный код человека/группы, одинаковый на всех его клипах; без персональных данных |
| `split` | `calibration` или `control`; зафиксировать до просмотра результатов |
| `permission` | `allowed: true`, `reference`: локальный код документа разрешения; не имя или содержание согласия. Ответственность за проверку разрешения остаётся у владельца набора |
| `video` | SHA-256 исходного файла (64 hex в нижнем регистре), точная `durationMs` из браузера; путь хранится только в локальном индексе |
| `exercise`, `variant` | `squat` + `bodyweight-side` либо `pushup` + `pushup-side`; не смешивать варианты |
| `view` | `side`, `unsuitable`, `unknown`, независимо от видимости суставов; категория всего клипа |
| `conditions` | Неличные теги темпа/света/одежды/перекрытия; свободный массив строк |
| `annotation` | `revision`, `source: human/synthetic`, `reviewer: coach/unreviewed`, `protocolVersion: playfit-validation-v1`, `rulesVersion: provisional-side-v1` |
| `sideConfirmationsMs` | Отсортированные уникальные таймкоды явного ручного подтверждения профиля. Пусто по умолчанию. Это операторский ввод, а не уверенность модели; после сброса подтверждение не восстанавливается автоматически |
| `unassessable` | Массив `{startMs, endMs, reason}` для глобально неразмечаемых участков; может быть пуст. Перекрытия объединяются. Исключаются время и пересекающие попытки |
| `attempts` | Упорядоченные непересекающиеся интервалы попыток, включая неполные; может быть пуст для отрицательного клипа |

Попытка: `{id, startMs, endMs, outcome, criteria}`. Уникальный `id` — строка; `0 <= startMs < endMs <= durationMs`. Касание соседних границ допустимо. `outcome`: `complete`, `incomplete`, `insufficient_data`. Последний используется, когда движение заметно, но исход не определяется; не заменяйте неизвестное на полный повтор.

В `criteria` **обязательны все** `depth`, `extension` и `lean` для приседаний либо `line` для отжиманий. Каждый содержит `status: passed/deviation/unassessed`, необязательный `note`. При `unassessed` объяснение `note` обязательно. `onsetMs` разрешён только для `deviation`, лежит внутри попытки и означает самое раннее наблюдаемое начало отклонения. Если оно неизвестно, опустите onset; это исключит лишь задержку, а не TP/FN. Пустой `criteria` и отсутствующий критерий не означают «всё хорошо» — валидатор отклонит файл.

Для реального материала `annotation.source` должен быть `human`. `reviewer: coach` ставится после фактической проверки специалистом конкретной разметки; это не подтверждение клинической обоснованности правил. Наблюдаемую разметку и её ревизии храните отдельно от порогов реализации.

Сырые выгрузки включают модель/правила/код в `metadata`, исходные таймкоды кадров, стороны/ракурс/достаточность, причины пропусков, публичные замечания, итоговые попытки с `detectedAtMs` и `remarkDetectedAtMs`, технические времена. Изображений, аудио и координат скелета в формате нет. Если детектор не обнаружил человека, кадр всё равно присутствует с причиной нехватки данных.

Локальный индекс рекомендуется вести так (CSV или JSON; **не коммитить**):

```text
clipId | relativeVideoPath | annotationPath | participantGroupId | split | permissionCode
clip-001 | recordings/clip-001.mp4 | labels/clip-001.annotation.json | group-a | calibration | permit-a
clip-002 | recordings/clip-002.mp4 | labels/clip-002.annotation.json | group-b | control | permit-b
```

Нельзя переносить одного человека/дубли/нарезки одной записи между split. Проверяйте индекс по `participantGroupId` и хешам до первого прогона. Текущий инструмент сравнивает один клип и не проверяет весь частный индекс; отчёт сохраняет split, чтобы смешение оставалось заметным. В публичном агрегированном отчёте оставьте только размеры групп, распределения условий, версии и агрегаты — без исходных видео, сырых экспортов и узнаваемых деталей.
