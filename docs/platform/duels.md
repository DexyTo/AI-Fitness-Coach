# Асинхронные дуэли — этап 7

Два аккаунта принимают один снимок каталожной программы, выполняют его независимо через камеру и окончательно отправляют по одному результату. Формула, нулевые/отсутствующие результаты и бонусы зафиксированы в [game-rules.md](game-rules.md#асинхронные-дуэли--duels-v1-этап-7). Код, цель, срок и `rules` неизменяемы с создания. Создание не отправляет сообщения другим людям.

## Страницы и сценарий

- `/competitions/duels` — мои дуэли, фильтры «В ожидании»/«Все», обновление, ввод кода, создание.
- `/competitions/duels/new` — каталог, параметры каждого шага, срок 1/24/72/168 часов. API допускает целые 1–168 часов.
- `/competitions/duels/invite/:code` — условия перед принятием. Нужен аккаунт; приглашение содержит только публичные никнейм/аватар создателя, план, формулу, срок и состояние. История и попытки здесь недоступны даже знающему код.
- `/competitions/duels/:id` — приватные детали для двух участников, статус, код с ручным fallback копирования, запуск, записанная работа, окончательная отправка, сравнение и объяснение наград. Пока дуэль не завершена, чужой черновик/балл не показываются. По завершении доступны сопоставимые баллы и исходы обоих, без чужой подробной истории.
- `/overview` — мои непринятые приглашения и принятые/ожидающие дуэли. Это приглашения, созданные пользователем; входящее приглашение по коду становится его дуэлью после явного принятия. Обзор и профиль показывают восьмой значок и отдельный `duelXp`.

Гость сохраняет базовую тренировку. Для дуэлей обязателен вход. После принятия отказаться через отмену нельзя. Вклад остаётся ограниченным целью, ничья допустима. Нет чата, трансляции, WebSocket, автоматического подбора соперника и проверки подлинности клиентских результатов.

## Автомат

| Состояние | Переход |
| --- | --- |
| `invited` | создатель отменяет → `cancelled`; другой аккаунт принимает → `accepted`; дедлайн → `expired` |
| `accepted` | первая окончательная отправка → `waiting`; дедлайн без отправок → `expired` |
| `waiting` | вторая своевременная отправка → `completed`; дедлайн с одной положительной отправкой → `completed`; с одной нулевой → `expired` |
| `completed`, `cancelled`, `expired` | терминальные; события и награды не меняются |

Две своевременные нулевые отправки дают `completed`/ничью, но без бонусов. При единственной положительной отправке исходы — победа/поражение из-за отсутствия отправки, бонус и значок только отправившему с положительным баллом. При полном отсутствии отправок или единственной нулевой — истечение без наград. Черновик не считается отправкой.

## API

Все маршруты требуют сессию. Схемы закрытые, произвольные userId, источник и ссылки на историю не принимаются. Изменения требуют `x-playfit-request: 1`; UI также передаёт ожидаемый `x-playfit-user`. Ошибки общие `{error:{code,message,requestId}}`.

| Метод и путь | Вход | Выход / поведение |
| --- | --- | --- |
| `GET /api/duels` | — | `{duels:DuelView[]}` только владельца, с финализацией просроченных |
| `POST /api/duels` | `{requestId,program:ProgramPlan,hours}` | `{duel}`; 201 новый / 200 точный повтор; изменённый повтор 409. Проверяется актуальный каталожный шаблон, допускаются параметры его шагов |
| `GET /api/duel-invitations/:code` | 16 hex-символов, регистр не важен | `{invitation:DuelInvitation}` без участников/сессий/результатов |
| `POST /api/duel-invitations/:code/accept` | `{}` | `{duel}`; повтор участником возвращает его прежнюю дуэль; самоприглашение/третий/закрытый код 409 |
| `GET /api/duels/:id` | — | `{duel}`; чужому 404, финализация по серверному времени |
| `POST /api/duels/:id/cancel` | `{}` | только своё `invited`, точный повтор отмены допустим |
| `POST /api/duels/:id/run` | `{}` | `{id,createdAt,snapshot}`; один серверный ID на участника, 201 новый / 200 существующий, в том числе после reload |
| `PUT /api/duels/:id/draft` | `{revision,record:ProgramRecord}` | `{revision}`; последовательно 1,2,…; точный повтор текущей ревизии допустим; устаревшее изменение 409 |
| `POST /api/runs/:id/complete` | `{record}` точно из черновика | общий `{result:AccountResult}`; окончательная неизменяемая отправка. Новый результат 201, точный повтор 200, изменение/поздняя первая отправка 409 |

`DuelView.myAttempt` доступен только текущему участнику: `{run:{id,createdAt,snapshot}|null,revision,draft:ProgramRecord|null}`. `participants` содержит userId, никнейм, аватар, слот, submittedAt и итоговый event либо null. Никаких чужих run/result ID и подробных записей. Общий результат сохраняется в личной истории только при окончательной отправке. До этого черновик не создаёт progression/workout XP.

`DuelPersistence` записывает завершённые шаги, перед переходом ждёт подтверждения. Потерянный ответ повторяет с тем же payload/revision. Сервер запрещает заменять уже записанные шаги; после reload `ProgramController.restore` начинает следующий шаг с новым анализатором и подготовкой камеры. Остановленный неполный шаг можно отправить как итог, переиграть его нельзя. Если записанного шага ещё нет, повторный вход использует прежний run ID. Текущие кадры и незаписанные подходы не восстанавливаются. Восстановление обычных программ/испытаний не добавлено.

## Хранение и атомарность

`007_duels.sql` не меняет старые миграции и не создаёт backfill:

- `duels`: уникальные `(creator_id,request_id)`, случайный 64-битный `code`, JSON исходного запроса, `task_json` и `rules_json` (версия, точная формула, масштаб и бонусы), UTC-сроки/состояние. SQL-триггеры замораживают снимки и проверяют переходы.
- `duel_participants`: уникальные `(duel_id,user_id)` и `(duel_id,slot)`, slot только 1/2; слот 1 принадлежит создателю, слот 2 — другому аккаунту, вставка только в приглашение.
- `workout_runs.duel_participant_id`: nullable; UNIQUE для единственной сессии. Проверяется владелец и отсутствие одновременного контекста испытания, связь неизменяема. Прежние запуски сохраняют NULL.
- `duel_drafts`: одна изменяемая запись с ревизией на участника; после отправки изменение запрещено.
- `duel_submissions`: одна неизменяемая запись на участника, уникальный FK result_id на progression_events, score 0–10000, submitted_at.
- `duel_events`: PK(duel_id,user_id), nullable result_id (для отсутствующей отправки), event_at, rules_version, receipt_json `{outcome,reason,score,xp,points,eventAt}`. Без последующего UPDATE/DELETE.

Создание/принятие/отмена/запуск/черновик выполняются под BEGIN IMMEDIATE. Общая окончательная отправка проверяет снимок, порядок и агрегаты, затем допуск дуэли/черновик/срок, сохраняет workout result, progression, обычные XP, submission, возможные итоговые события обоих, бонусы и значки в одной immediate-транзакции. Ошибка откатывает всё. Чтения списка, деталей, приглашения, обзора и действия финализируют просроченные дуэли транзакционно; отдельный scheduler не нужен. Повторный запрос никогда не выдаёт валюту второй раз.

В `AccountResult.reward` остаётся обычная workout-награда. Бонус дуэли и исход — в `DuelView.participants[].event`, после финализации. Значок первого участника может появиться в его result receipt позже, когда отправится соперник или наступит срок; это не повторная workout-награда. Бонусы отражаются в progression.xp/duelXp/competitionPoints.

## Контракт для рейтинга этапа 8

Источник соревновательных очков — `reward_ledger` с `currency='competition_points'`, `source_type='duel'`, `source_id=duel.id`, user_id и event_at. XP рейтинговыми очками не является. Нулевые/отсутствующие итоги не создают строки валюты.

`duel_events` хранит и исходы без наград. Для двух своевременных отправок event_at равен серверному времени второй; для финализации по сроку — ends_at, даже если впервые прочитали позже. Использовать эти UTC-события и общие projectDay/projectWeek (Europe/Kyiv), а не время чтения, клиентскую дату или время архива. События, бонусы и значки не меняются при редактировании/архивировании программы или истории. Демонстрационные участники и рейтинг этим этапом не добавлены.

## Проверки и ограничения

`server/duels.test.ts`: синтетические результаты для двух/трёх аккаунтов, два DB-соединения, повтор принятия/создания/запуска/отправки/финализации, чужая история/черновик, самоприглашение, отмена, фиксированные часы/точный дедлайн, ничья/победа/нулевые и отсутствующие отправки, нормировка/округление, однократные валюты/значок, откат финализации, перезапуск, снимок после изменения/архива шаблона, миграция с этапа 6. `src/programs/controller.test.ts` проверяет восстановление записанных шагов без кадров предыдущего анализатора.

Фактический проход UI (включая 1440/390 px и два изолированных браузерных аккаунта) в этой среде заблокирован: Browser Use возвращает ERR_BLOCKED_BY_CLIENT для localhost/127.0.0.1; Windows Computer Use завершил доступ из-за невозможности уверенно определить URL. Это ограничение проверки, не подтверждение визуального качества. Камера и точность движения на людях не проверялись.
