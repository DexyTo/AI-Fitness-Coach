# Личные программы и избранное — этап 4

Реализованы `/my-programs`, `/programs/new`, `/programs/:id/edit`, `/favorites`. В каталоге `/programs` видны общие шаблоны и личные программы текущего аккаунта, источник и версия подписаны на карточках и деталях. Профиль содержит переходы к конструктору и коллекции, а также первые три реальные избранные программы. Гость видит каталог и объяснение необходимости входа для сохранения. Общий контроллер, анализатор, ProgramPlan и ProgramRecord этапа 3 сохранены: [контракт запуска и результата](programs.md).

## Владение и API

Личные программы закрыты автором: никто другой, включая гостя, не получает их через список, детали, копирование или запуск. Редактирование и архивирование разрешены только владельцу личной программы. Общие шаблоны читают, запускают и копируют все; для сохранения копии нужен аккаунт. Глобального редактора и социальной публикации нет. Владелец и источник назначаются сервером, не принимаются в форме. Чужой/отсутствующий/архивный объект возвращает 404; для нового запуска недоступного либо изменённого шаблона — 409 PROGRAM_CHANGED. Все изменения используют прежние cookie, CSRF и проверку X-PlayFit-User; клиент отправляет ожидаемого владельца также при чтении приватных данных.

| Метод и путь | Запрос / результат |
| --- | --- |
| GET `/api/programs` | `{programs: ProgramPlan[]}` — активные общие + собственные личные |
| GET `/api/programs/:id` | `{program: ProgramPlan}` доступного активного шаблона |
| GET `/api/me/programs` | `{programs}` только собственных активных личных; требует вход |
| POST `/api/programs` | `ProgramDraft` → 201 `{program}` с новым UUID, version=1, origin=personal |
| PUT `/api/programs/:id` | `{...ProgramDraft,version}` → `{program}` с version+1; устаревшая версия → 409 |
| POST `/api/programs/:id/copy` | `{version}` исходного шаблона → 201 `{program}`; устаревшая версия → 409 |
| DELETE `/api/programs/:id` | `{ok:true}`; собственная личная архивируется, повтор безопасен |
| GET `/api/me/favorites` | `{programs}` активных доступных избранных; требует вход |
| PUT `/api/programs/:id/favorite` | `{ok:true}`, повтор не создаёт дублей |
| DELETE `/api/programs/:id/favorite` | `{ok:true}`, удаляет только собственную связь; повтор безопасен |

`ProgramDraft = Pick<ProgramPlan,'title'|'description'|'steps'>` из `shared/programDraft.ts`. ID/порядок/параметры шагов совпадают с общим ProgramPlan, отдельной схемы упражнений конструктора нет. Серверная JSON Schema переиспользует поля `planSchema`; дополнительно общая проверка требует непустое после trim название и уникальные ID шагов. Неизвестные поля и типы упражнений отклоняются. Название 1–100 символов, описание 0–1000; 1–12 шагов. Только squat/pushup. Целые sets 1–100, reps 1–1000, restSeconds/transitionSeconds 0–3600. Это технические пределы, а не рекомендации по нагрузке. Переход последнего шага сохраняется, но при запуске не используется.

Новый шаг имеет пустые поля нагрузки/отдыха: пользователь заполняет их сам. Перестановка вверх/вниз перемещает весь шаг с его параметрами и постоянным ID. Копирование сохраняет название, описание, порядок, параметры и ID шагов выбранного сохранённого шаблона, но создаёт отдельный UUID программы, владельца и version=1. Изменённые на экране запуска цели относятся только к этой сессии; копирование и редактор берут сохранённый шаблон. Избранное не копируется. Создание и копирование не имеют requestId: повтор отдельного POST создаёт новый объект, кнопки блокируются на время запроса. Идемпотентность избранного и запуска гарантируется отдельно.

## Миграция и неизменность прошлого

`004_builder.sql` дополняет прежнюю общую таблицу `programs` полем `archived_at`, индексом владельца/архива. `owner_id`, `origin`, `version` и `program_steps` уже существовали; старые миграции не меняются. Добавлены:

- `program_versions(program_id,version,snapshot_json,created_at)`, PK `(program_id,version)`, FK программы; миграция сохраняет текущие версии всех существующих шаблонов с упорядоченными шагами. Триггеры запрещают UPDATE/DELETE редакций.
- `program_favorites(user_id,program_id,created_at)`, составной PK исключает дубли, оба FK включены. Удаление из избранного не затрагивает чужие связи.

Создание/копирование/редактирование записывают текущий шаблон, шаги и полный снимок редакции в одной транзакции. Конфликт версии и ошибка шага откатывают всю запись. API редактирования выпускает следующую версию даже при одинаковых значениях. Для будущего служебного изменения каталога также нужно выпускать новую редакцию и сохранять её снимок транзакционно; публичного API для такого изменения нет.

Удаление в UI означает архивирование: строка программы, шаги, редакции и связи остаются в БД, активные списки и избранное фильтруются. Физического DELETE и каскадного удаления результатов нет. Новые чтения/запуски/копии архива недоступны; прямые детали объясняют, что старые итоги сохранены. Восстановление архива в интерфейсе не реализовано.

Новый запуск проверяет доступность, владельца и актуальную версию шаблона, его метаданные и упорядоченный состав. Цель и отдых можно настроить под конкретный запуск как раньше. Принятый `workout_runs.snapshot_json` не зависит от текущего шаблона: повтор исходного requestId и завершение начатого запуска работают после правки и архивирования. Результат содержит полный исходный ProgramPlan, исходную версию, порядок и результаты детей. Ссылка `/history/:resultId` читает результат владельца независимо от доступности шаблона.

Будущие испытания и дуэли должны копировать полный ProgramPlan в свой неизменяемый снимок при создании/принятии задания и связывать новые камерные запуски именно с этим снимком. Нельзя подменять принятое задание текущей строкой programs или перерасчитывать прошлое при редактировании. Контракт ProgramRecord v2 не менялся. Этап 5 добавляет [XP и достижения](game-rules.md), сохраняя эти контракты снимков. Соревнования пока не реализованы.

## Форма и черновики

Клиент проверяет те же пределы и блокирует сохранение неполной формы. Ошибка сервера оставляет поля, повтор выполняется кнопкой сохранения. Локальный `sessionStorage` хранит черновик по `playfit.builder.v1:<userId>:<programId|new>`: возврат после SPA-перехода или reload восстанавливает заполнение, включая пустые числовые поля. Это черновик вкладки, а не серверная программа и не перенос между аккаунтами. Закрытие/обновление изменённой формы дополнительно вызывает beforeunload. Успех очищает черновик; «Сбросить черновик» возвращает актуальную загруженную версию. Черновик прежней версии не перезаписывает новый шаблон: показано объяснение, сервер отклонит устаревший PUT. При запрете sessionStorage есть предупреждение; восстановление после ухода тогда недоступно. После закрытия вкладки черновик не гарантируется.

## Проверки

`npm test`, `npm run check:server`, `npm run test:server`, `npm run build`. Новые тесты: миграция старой БД и повтор, сохранность порядка, запрет изменения редакций, права гостя/второго аккаунта на чтение/правку/удаление/копию/избранное, неизвестные поля/упражнения/дубли/пределы, конфликт редакции, точность копии, транзакционный откат, избранное после перезапуска и повторов, завершение и повтор запуска/результата после архивирования. Проверка UI описана в STATUS.md текущего цикла. Синтетическое демо проверяет сценарий и интерфейс; точность распознавания на людях не проверялась.
