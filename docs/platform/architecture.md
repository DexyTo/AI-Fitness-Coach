# Локальная платформа: основа и аккаунты

Этапы 2–4 реализованы поверх основы: [аккаунты и история](accounts.md), [каталог, снимки и результаты программ](programs.md), [конструктор и избранное](builder.md). Ниже сохранены детали основы; расширения API описаны в связанных документах.

Реализовано 20.10.2026. Клиент React 19 + TypeScript + Vite, React Router 7 в declarative mode. Сервер Fastify 5 + TypeScript, SQLite через закреплённый better-sqlite3 12.11.1. Установка и запуск проверены на Windows, Node.js 22.13.1 / npm 10.9.2. Требуется Node.js 22.12+ в ветке 22 либо 24 LTS. Версия better-sqlite3 13.0.3 на этой машине аварийно завершала процесс при открытии БД; 12.11.1 успешно выполняет запросы и тесты, Python/компилятор C++ не потребовались.

## Структура и границы

- `src/` — браузер. MediaPipe, камера, локальные файлы, поток точек и анализатор остаются на устройстве. `src/exercises/`, `src/pose/` и автомат тренировки не переписаны.
- `src/main.tsx` — BrowserRouter; `src/App.tsx` — общий layout (шапка, навигация, skip-link) и маршруты. Существующие TrainingView/HistoryView используют прежние контракты.
- `src/routing/selection.ts` — разрешённые значения выбора и сериализация query string.
- `server/config.ts` — проверка настроек, стабильный корень проекта.
- `server/database.ts` — открытие БД, PRAGMA, исполнитель миграций.
- `server/migrations/*.sql` — отслеживаемые SQL-миграции.
- `server/app.ts` — создание Fastify, схемы и ошибки; `server/index.ts` — запуск/остановка; `server/migrate.ts` — отдельная команда.
- `.server-build/server/` — серверный JS, `.server-build/shared/` — общие контракты; `dist/` — клиент. Сервер читает SQL из `server/migrations/` и после компиляции; для переноса сервера нужны и скомпилированные файлы, и эта папка, и зависимости.

Сервер не импортирует browser-only модули и не принимает видео. На этапе 1 история остаётся **гостевой**, в `localStorage` по ключу `playfit.workouts.v1`, с конвертом и `WorkoutRecord` v1 из [контракта истории](../training-history.md). Обещание локальной гостевой истории соответствует реализации. Этап 2 добавляет авторизацию и серверную историю аккаунтов; этап 5 добавляет [игровой опыт](game-rules.md). Этап 6 добавляет [испытания](challenges.md); дуэли и рейтинг пока не реализованы.

## Запуск и конфигурация

```sh
npm install
npm run db:migrate
npm run dev
```

`npm run dev` использует concurrently с `--kill-others`: запускает `dev:server` (tsx watch) и `dev:client` (Vite), завершает соседнюю команду при выходе любой из них. Ctrl+C завершает деревья процессов, в том числе на Windows. Не нужно отдельно оставлять API в фоне. Чужой уже запущенный Vite не останавливается: новый клиент выбирает следующий свободный порт. Адрес берётся из вывода Vite, обычно 5173.

| Настройка | По умолчанию | Проверка |
| --- | --- | --- |
| `API_PORT` | `3001` | целое 1–65535, без пробелов/суффиксов |
| `DATABASE_PATH` | `data/playfit.sqlite` | непустой файловый путь, без NUL, не `:memory:` |
| host | `127.0.0.1` | фиксирован; API не открывается в LAN |

Необязательный `.env` загружается Node/tsx; Vite читает тот же файл для proxy `/api`. Переменные окружения имеют приоритет. После изменения настроек перезапустить общую команду. Путь БД разрешается относительно корня проекта, абсолютный путь также допустим. Стандартные БД/WAL/SHM, `.env` и `.env.*` (кроме примера), `.server-build/` исключены точными правилами Git. Для нестандартного пути внутри checkout нужны собственные точные исключения; предпочтителен путь вне репозитория. Миграции не игнорируются.

Дополнительные команды:

| Команда | Назначение |
| --- | --- |
| `npm test` | все тесты клиента и сервера |
| `npm run test:server` | API, конфигурация, SQLite/миграции |
| `npm run check:server` | отдельная проверка серверного TypeScript |
| `npm run build:server` | сборка серверного JS |
| `npm run build` | сборка сервера, проверка клиента, сборка клиента |
| `npm run start:server` | собранный API, миграции при старте |
| `npm run preview` | собранный клиент + proxy (API запустить отдельно) |

В Windows PowerShell допустимо везде заменить `npm` на `npm.cmd`. Обязательных облаков, Docker, Python, внешних AI API и seed-данных нет.

## Миграции и сохранность

При открытии БД создаются недостающие каталоги, включаются `foreign_keys=ON`, WAL и `busy_timeout=5000`. Исполнитель запускается отдельной командой и автоматически перед listen API. `BEGIN IMMEDIATE` сериализует миграции; все ожидающие SQL и записи журнала применяются одной транзакцией. Ошибка откатывает их вместе. Старые данные не очищаются.

`schema_migrations`: `version INTEGER PRIMARY KEY`, уникальное `name TEXT`, SHA-256 `checksum TEXT`, `applied_at TEXT` в ISO UTC. Имена `NNN_name.sql`, версии уникальны, новые версии идут после применённых. Журнал создаётся транзакционно. Отсутствующая/изменённая применённая миграция останавливает запуск, чтобы не скрывать рассогласование. CRLF нормализуется до LF перед подсчётом checksum; старые миграции не редактировать, изменения оформлять следующей.

`001_foundation.sql` создаёт только `platform_metadata(key TEXT PRIMARY KEY, value TEXT NOT NULL)` с маркером `schema=foundation-v1`. Таблицы пользователей/результатов заранее не создаются. Отдельного seed на этом этапе нет; будущие seed должны быть повторяемыми и не стирать пользовательские строки.

## API и ошибки

`GET /api/health` выполняет реальный запрос к `schema_migrations`:

```json
{ "status": "ok", "database": "ok", "schemaVersion": 5 }
```

Query-параметры health запрещены JSON Schema; Fastify не удаляет неизвестные поля и не приводит строки к числам автоматически. Для следующих API задавать полные схемы body/query/params и границы значений. Лимит тела — 64 KiB. Успешный health подтверждает доступ к текущей БД, но не работоспособность будущих функций.

Все ошибки API, включая 404, некорректный JSON, валидацию, размер тела и внутренние сбои:

```json
{ "error": { "code": "INVALID_REQUEST", "message": "Некорректный запрос.", "requestId": "req-1" } }
```

Коды: `INVALID_REQUEST` (400), `NOT_FOUND` (404), `PAYLOAD_TOO_LARGE` (413), `UNSUPPORTED_MEDIA_TYPE` (415), `REQUEST_ERROR` (прочие 4xx), `INTERNAL_ERROR` (500). Статус сохраняется; произвольные тексты ошибок, SQL, стек и входные секреты в ответ не включаются. requestId генерируется Fastify. Логи редактируют Authorization/Cookie/Set-Cookie; тела запросов не логируются автоматически. Ошибка старта выводит короткую локальную диагностику без значений секретов. Проверки конфигурации выполняются до listen.

## URL и навигация

- `/` — главная и выбор.
- `/training?exercise=squat&mode=camera` — тренировка выбранного упражнения/источника.
- `/history` — гостевая либо серверная история текущего аккаунта.
- `/history/:id` — серверные детали своего результата.
- `/login`, `/register`, `/profile`, `/overview` — вход, регистрация, профиль и персональный обзор.
- `/programs`, `/programs/:id` — каталог, настройка, прохождение и общий итог программы.
- `/my-programs`, `/programs/new`, `/programs/:id/edit`, `/favorites` — личные программы, конструктор и избранное аккаунта.
- Любой неизвестный путь — русская 404 с переходом на главную.

На известных страницах query приводится через replace к двум разрешённым параметрам. `exercise`: `squat`, `pushup`; `mode`: `camera`, `video`, `demo`. Недопустимые/отсутствующие значения заменяются на `squat/camera`, неизвестные и повторные параметры убираются (у повторных берётся первое значение). Выбор на главной заменяет URL; переходы между экранами добавляют запись в историю браузера. Навигационные ссылки сохраняют параметры. Назад/вперёд и обновление восстанавливают экран/выбор; тренировочный runtime при уходе размонтируется и освобождает ресурсы. Цель и файл не сериализуются, незавершённая сессия после обновления не восстанавливается. Реальная камера автоматически не включается.

Vite dev/preview обеспечивают SPA fallback. На внешнем хостинге потребуется отдельный fallback на `index.html` с исключением ресурсов и `validation.html`; статический хостинг не предоставляет Fastify/SQLite.

## Выполненные проверки этапа

`npm test`: 170 тестов / 12 файлов, включая 19 серверных проверок и проверку URL; `npm run check:server`, `npm run build`, `git diff --check` успешны. SQLite проверена на чистом временном пути, повторе с сохранением пользовательской строки, переоткрытии, FK/WAL, откате DDL/данных/журнала, последующем применении исправленного SQL и контроле изменённых/дублирующихся миграций. API проверен через Fastify inject, затем по настоящему HTTP напрямую и через Vite proxy; собранный сервер — с альтернативными портом и новой БД, вместе с preview клиента.

В браузере реально проверены главная, тренировочные экраны обоих упражнений и всех трёх источников до запуска, история (пустая и с записью), 404, переходы, refresh, back/forward и неверные query-параметры. Проверены компоновки 1440 и 390 CSS px без горизонтального переполнения. Демо squat 1×1 с отдыхом 0 завершилось за 3 с и после reload истории сохранило запись с меткой «Синтетическое демо». Console error/warn не обнаружены. Ctrl+C общей команды освободил порты API и клиента; ранее работающий Vite другого процесса сохранён. Камера, реальное видео и точность распознавания на людях не проверялись.

На момент проверки `npm audit --omit=dev` не выявил уязвимостей; общий audit сообщает 4 уязвимости существующих dev-зависимостей (Vitest/его зависимости и source-map-js). Мажорное обновление тестового инструментария не входило в этот этап.
