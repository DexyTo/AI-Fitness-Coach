# Программы: каталог, снимки и результаты (этапы 3–4)

Конструктор, личные программы, избранное, права, редакции и архивирование реализованы на этапе 4: [API и контракт конструктора](builder.md). Ниже — общий неизменившийся путь прохождения и результата.

Реализованы `/programs`, `/programs/:id`, общий итог и история программ гостя/аккаунта. Каталог содержит семь учебных шаблонов из приседаний и отжиманий. Поиск работает по названию/описанию, фильтры — по составу и числу шагов. Числа в шаблонах не являются персональными назначениями. Оценка времени использует 4 с на повтор плюс заданный отдых, без подготовки и пауз.

## Данные и API

Миграция `003_programs.sql` создаёт `programs` и `program_steps` с порядком шагов, FK и ограничениями. Семь шаблонов наполняются внутри миграции один раз; повтор миграций и перезапуск сохраняют изменения и пользовательские данные. Миграция 004 добавляет архив, неизменяемые редакции и избранное. Общая модель `origin: catalog | personal`, `ownerId`, постоянный ID и версия используется каталогом и конструктором. Новый запуск разрешён для активного каталожного или собственного личного шаблона.

`GET /api/programs` → `{programs: ProgramPlan[]}`; `GET /api/programs/:id` → `{program: ProgramPlan}`, неизвестный/недоступный ID → 404. Гость читает каталог, аккаунт — каталог и собственные личные программы. Полные типы находятся в `shared/program.ts`, схемы запросов — в `server/programs.ts`.

```ts
interface ProgramPlan {
  schemaVersion: 1;
  id: string;
  version: number;
  origin: 'catalog' | 'personal';
  ownerId: string | null;
  title: string;
  description: string;
  steps: {
    id: string;
    exercise: 'squat' | 'pushup';
    goal: { sets: number; reps: number; restSeconds: number };
    transitionSeconds: number;
  }[];
}
```

От 1 до 12 шагов с уникальными ID; подходы 1–100, повторы 1–1000, отдых/переход 0–3600 с, целые числа. Переход последнего шага не используется. Перед запуском можно изменить цели и время отдыха/перехода. Название, описание, источник, версия, состав и порядок соответствуют шаблону. Изменения формы не записываются в каталог.

Существующий `POST /api/runs` принимает также `{requestId,kind:'program',program:ProgramPlan,mode:'camera'|'demo',conditions}`. Ответ `{id,createdAt,snapshot}`; сервер связывает полный снимок с владельцем и устойчивым requestId. Повтор того же запроса возвращает тот же ID, конфликт содержимого — 409. Проверка актуального каталога выполняется только при новом запуске: уже принятый запрос можно повторить после изменения шаблона. `PROGRAM_CHANGED` предлагает заново открыть детали программы. При ошибке связи клиент сохраняет requestId; при изменении плана создаёт новый. Гостевой запуск получает локальный ID и снимок без серверного аккаунта.

`POST /api/runs/:id/complete` принимает `{record:ProgramRecord}` наряду с прежним WorkoutRecord v1:

```ts
interface ProgramRecord {
  schemaVersion: 2;
  kind: 'program';
  id: string;               // run.id
  date: string;             // серверный run.createdAt для аккаунта
  mode: 'camera' | 'demo';
  conditions: string;
  program: ProgramPlan;     // точный снимок запуска
  ended: 'completed' | 'interrupted';
  duration: number;         // секунды, включая паузы и переходы
  steps: WorkoutRecord[];  // упорядоченный префикс реально записанных шагов
}
```

В программе нет общего поля `exercise`: каждый дочерний WorkoutRecord v1 имеет своё упражнение, цели, версии правил, подходы и попытки. ID ребёнка — `${run.id}:${zeroBasedStepIndex}`. Дочерние результаты отдельно в историю не записываются. Общие показатели в UI вычисляются из детей, счётчик полной цели не включает неполные и неоценённые попытки; замечания сохраняются отдельно.

Сервер проверяет владельца, полный снимок, ID и порядок детей, соответствие упражнений/целей/источника/условий, хронологию и длительности, вложенные критерии и агрегаты попыток. Промежуточные дети должны иметь все завершённые подходы; незавершённый ребёнок допустим только последним. `completed` разрешён лишь со всеми шагами и завершёнными подходами. Пустой `interrupted` допустим при выходе до первого шага. Ручное завершение подхода считается завершением подхода, но число достигнутых целей показывается отдельно по фактическим полным повторам. Общий лимит 5000 попыток, 4 MiB и 7 суток сохраняется.

Сохранение использует таблицы этапа 2: `workout_runs.snapshot_json` и `workout_results.record_json`, `source='training',source_version=2`. Первый ответ 201, равнозначный повтор 200, конфликт результата 409. Изменение/удаление каталога не влияет на принятый снимок и прошлый результат. Архивирование, изоляция аккаунтов и однократность сохраняются; повтор сохранения не восстанавливает скрытый результат. Профиль считает программу одной записью, полные повторы суммирует из детей, демо отделяет от личных показателей. Наград в этом этапе нет.

## Контроллер и источники

`ProgramController` (`src/programs/controller.ts`) управляет порядком над прежним `TrainingController`. Каждый шаг монтирует отдельную TrainingView с зафиксированной целью. Старт шага явный; анализатор и подсказки создаются заново, старые попытки не переносятся. Подготовка, пауза, ручное завершение подхода и отдых между подходами используют прежний контроллер. После завершения ребёнка источник останавливается, камера освобождается и детектор закрывается. Переход отсчитывает отдельный отдых с паузой/продолжением; по его окончании пользователь явно переходит к новому упражнению и заново запускает источник/проверку готовности.

Кнопка «Прервать программу» фиксирует текущий подход как прерванный и сохраняет общий итог с фактическим префиксом. На переходе сохраняются только предыдущие дети; до запуска первого шага результат пустой. Будущие шаги не создаются. Повтор запуска доступен после подтверждённого сохранения и возвращает план этой сессии на настройку с новым run/request ID. Ошибка общего сохранения оставляет повтор и экспорт JSON; подтверждение показывается только после успешного ответа.

Для программы разрешены камера и синтетическое демо. Демо проходит тот же контроллер, честно помечено, не проверяет MediaPipe и не начисляет наград. Видеофайл доступен в прежнем одиночном сценарии: программа не определяет тип движения в смешанной записи. Все кадры и поток точек остаются на устройстве.

## Совместимость и ограничения

- WorkoutRecord v1, `playfit.workouts.v1`, одиночная тренировка, сравнение и явный импорт v1 не изменены. Программы не маскируются под одиночное упражнение и не попадают в сравнение v1.
- Гостевые программы хранятся отдельно в `playfit.programs.v2` как `{schemaVersion:2,programs:ProgramRecord[]}`. История показывает оба раздела, программы можно экспортировать/удалять отдельно. Повреждённый раздел не перезаписывается, доступен экспорт исходного JSON. Очистка/экспорт прежнего раздела одиночных тренировок относится только к v1.
- Аккаунт экспортирует `{schemaVersion:1,records:WorkoutRecordV1[],programs:ProgramRecord[],accountResults}`. `records` сохраняет читаемость прежним v1-парсером; `programs` сохраняет исходные run/child ID для внутренних связей. Метаданные происхождения содержат серверный ID результата и recordId. Отдельный экспорт программы — `{schemaVersion:2,programs:[record]}`.
- Импорт гостевых программ и загрузка JSON не реализованы. Существующая кнопка импорта аккаунта работает только с одиночными v1-записями; об этом явно сказано в интерфейсе. Импорт программ остаётся отдельным будущим расширением без наград.
- Незавершённый запуск, изменённый план и ещё не подтверждённый итог живут в памяти. Reload/закрытие предупреждают о потере, но восстановление по run ID и фоновое сохранение детей не реализованы. Для сохранения перед уходом нужно воспользоваться явным прерыванием программы; уход через навигацию/смена аккаунта не завершает запуск автоматически. Не выдавать такой запуск за завершённый.
- Конструктор создаёт новые редакции и сохраняет снимки, проверяет ownerId на сервере. Существующие результаты не зависят от текущих строк каталога. Принятые программы не редактируются в процессе прохождения.
- Камера и реальные видео/точность на людях не проверялись. Результаты клиента не являются доказательством подлинности движения. Внешняя проверка точности отложена независимо от этого этапа.

Запуск прежний: `npm install`, `npm run db:migrate`, `npm run dev`. Проверки: `npm test`, `npm run check:server`, `npm run test:server`, `npm run build`.
