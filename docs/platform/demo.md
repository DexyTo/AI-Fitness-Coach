# Рейтинг и показ платформы

Этапы 1–8 реализованы. Локальная учебная платформа: аккаунт → программа → серверный результат → XP/достижение → испытание/дуэль → рейтинг. Проверка точности распознавания на людях отложена и не объявляется выполненной.

## Запуск и наполнение

Node.js 22.12+ в ветке 22 либо 24+, без Docker, Python и внешних AI API:

```sh
npm install
npm run db:migrate
npm run db:seed:challenges
npm run db:seed:demo
npm run dev
```

Vite печатает адрес клиента (обычно http://127.0.0.1:5173). API по умолчанию 127.0.0.1:3001. `API_PORT` и `DATABASE_PATH` задаются в `.env` или окружении. Одна команда `dev` запускает обе части; Ctrl+C останавливает их. Для собранного варианта: `npm run build`, затем `npm run start:server` и `npm run preview` в двух терминалах с одинаковым API_PORT. SQL-файлы остаются нужны собранному серверу.

- **Обычный старт** применяет только миграции, сохраняет аккаунты и результаты. Миграция 003 наполняет семь каталожных программ без пользователей/наград.
- **db:seed:challenges** явно добавляет три задания текущей недели и анонс следующей. Не создаёт участников, результаты или балансы.
- **db:seed:demo** явно добавляет 12 вымышленных аккаунтов, два учебных испытания (завершённое и активное с прогрессом 1/3), связанные результаты программ, достижения и шесть дуэлей: победа/поражение, положительная ничья, ничья нулей без бонуса, ожидание второй отправки и принятое задание. Никаких реальных упражнений при этом не было.

Специальные публичные **учебные** логины `demo_01` … `demo_12`; пароль у них `PlayFitStudy2026`. `demo_01` — Лайм (победа, уровень 2, активное испытание), `demo_02` — Комета (поражение), `demo_03`/`demo_04` — ничья, `demo_07`/`demo_08` — нулевая ничья, `demo_09`/`demo_10` — ожидание, `demo_11`/`demo_12` — принято. Это вымышленные локальные аккаунты для показа; реальные пользовательские пароли и сессии не публикуются.

Seed — одна immediate-транзакция на календарную неделю Europe/Kyiv, batch `demo:platform-v1:<понедельник>`. У аккаунтов устойчивые ID `playfit-demo-01` … `playfit-demo-12`, у источников — ID с batch-префиксом. Повтор той же недели ничего не добавляет и не меняет награды, пароли, никнеймы и обычные данные. В новую неделю добавляются новые события, старые остаются. Коллизия зарезервированного логина с обычным аккаунтом останавливает и откатывает всю операцию, не переименовывая его. Ошибка начисления также откатывает всю партию.

Вымышленные записи имеют metadata `fabricated`/`detector=none` и условия «Вымышленный учебный результат · без камеры». Для проверки учёта они используют контракт camera-result, но принадлежат **только** неизменяемым участникам `demo_users`. Их XP/очки получают внутренние accountCompletion/completeChallenge/completeDuel/finalizeDuel, по обычным формулам; прямой записи произвольного баланса нет. Маркировка события определяется его владельцем в неизменяемом `demo_users`, а определения испытаний дополнительно содержат isDemo. Вход/текущий профиль возвращают isDemo, весь UI такого аккаунта имеет учебный баннер. Учебные и обычные аккаунты не могут принимать приглашения друг друга.

**Синтетическое демо тренировки** — другой сценарий: искусственные точки → анализатор → счётчик, mode=demo, без XP/достижений/соревновательных очков. Вымышленное наполнение платформы показывает уже сохранённые учебные события и их учёт. Ни один сценарий не доказывает работу камеры или точность MediaPipe на людях.

## Рейтинг и публичность

`/leaderboard` доступен гостю. Фильтры периода и участников сохраняются в URL; прямой адрес/reload/back/forward работают. В обычном режиме учебные участники исключены; `/leaderboard?mode=demo` показывает их отдельно с объяснением. Учебные испытания скрыты от обычного каталога/прямого доступа, обычные участники и счётчики испытаний не смешиваются с учебными.

`GET /api/leaderboard?period=week|all&mode=regular|demo&offset=0` (все параметры необязательны; по умолчанию week/regular/0):

- `{period,mode,startsAt,endsAt,timeZone,total,offset,limit:10,rows,me}`. UTC-границы у all равны null. rows/me: `{id,nickname,avatar,level,points,rank,isDemo}`. me — текущая сессия, не клиентский userId; вне первой страницы позиция считается по всей выборке. Без участия в выбранном режиме/периоде me=null, без очков строки не появляются.
- Суммируются только `reward_ledger.currency=competition_points`, source_type challenge/duel. XP/уровень не определяют место. Неделя через общую `projectWeek`: понедельник 00:00 включительно → следующий понедельник 00:00 исключительно, Europe/Kyiv с DST. Берётся неизменяемый event_at, а не дата клиента или чтения. UI показывает даты включительно по воскресенье.
- Схема competition ranking: равные очки → общее место, затем пропуск (`1,2,2,4`). SQL RANK вычисляется только по очкам; ID по возрастанию стабилизирует порядок внутри ничьей. Пагинация не меняет места. Равная группа может пересекать границу страниц.
- Перед чтением рейтинга и публичного профиля сервер финализирует просроченные дуэли. При позднем первом чтении время награды остаётся ends_at; завершение не переезжает в неделю чтения. Повторы безопасны.
- Есть загрузка, пустой рейтинг, отсутствие личного участия, несовпадение режима аккаунта, ошибка API с повтором и страница вне диапазона с возвратом к началу.

`/participants/:id`, `GET /api/participants/:id` → `{participant}` с **явно выбранными** полями: id, nickname, avatar, level, isDemo, points, открытые achievements `{id,title,earnedAt}` и до 10 последних соревновательных наград results `{kind,title,outcome,points,eventAt}`. В списке наград только события с положительными очками, это прямо указано в UI; нулевые исходы доступны участнику в его дуэли. Не выдаются login, хеш пароля, сессии, снимки заданий, условия съёмки, ID приватных результатов, видео, черновики и история тренировок. Собственный `/profile` остаётся отдельной страницей.

## Сценарий защиты (5–7 минут, без ожидания недели)

1. Запустить команды выше. Гостем открыть обычный рейтинг: на чистой БД он честно пуст. Переключиться на учебных участников: 12 человек, равные места, две страницы. Переключить неделю/всё время и раскрыть правила.
2. Войти `demo_01`: обзор с подтверждёнными учебными 120 XP, уровнем 2, открытыми значками, активным испытанием 1/3. Баннер объясняет вымышленность. Открыть историю, результат программы и его разбор: это сохранённый учебный пример без камеры.
3. В каталоге выбрать любую программу, снизить цель до 1×1 и отдых до 0, выбрать **Демо**, пройти оба шага. Увидеть сохранённый общий итог без XP. Вернуться в обзор: учебные очки и прежние значки не выросли от mode=demo. Это проверка UI/счётчика на синтетических точках.
4. Открыть «Соревнования»: активное учебное испытание с прогрессом и выполненное испытание с отдельной наградой. Открыть «Мои дуэли»: у `demo_01` победа, у `demo_02` после выхода/входа — тот же матч с поражением. У `demo_03`/`demo_04` — положительная ничья. У `demo_11`/`demo_12` — принятое задание, у `demo_09`/`demo_10` — ожидание. Не называть эти результаты реальными упражнениями.
5. Перейти в учебный рейтинг, открыть публичного участника с достижениями и наградами. Войти `demo_12`: его личная строка видна над первой страницей, хотя сам участник находится на второй (место 7 при равенстве очков). Обычный рейтинг по-прежнему отдельный.
6. Reload деталей/рейтинга, назад/вперёд между фильтрами; повторно выполнить seed и перезапустить приложение — аккаунты, результаты и очки сохраняются. Для повторного показа доступны прежние результаты; сброс БД не нужен.

## Сохранение и архивирование

Миграция 008 добавляет только demo_users, demo_seed_batches, неизменяемость принадлежности к демо и индекс рейтинга; старые таблицы/балансы не переписываются. Серверная история архивируется (archived_at), награды/значки/соревновательные события сохраняются. Архивирование/редактирование программ не меняет принятые снимки или прошлый рейтинг. Физического удаления аккаунтов и событий нет. Для резервной копии остановить сервер и сохранить файл DATABASE_PATH; при работающем SQLite нельзя копировать только основной файл без учёта WAL/SHM. Частные SQLite/WAL/SHM, env и материалы остаются вне Git по правилам проекта. Не удалять пользовательскую БД ради показа.

## Проверки и пределы

- Автоматически: npm test (включает сервер), npm run build. Новый server/leaderboard.test.ts проверяет ранг и ничьи, личное место вне страницы, лето/зиму/DST и точные границы недели, изоляцию учебных данных/приглашений/испытаний, whitelist публичного профиля, реальный вход учебным паролем, повтор и новую неделю seed, restart/migrate, сохранение обычного аккаунта, транзакционный откат и сквозной API-путь двух аккаунтов: программа → история → XP/значки → испытание → дуэль → рейтинг → архив. Результаты camera в этих тестах — явно искусственные fixture, не камера.
- Финальный `npm test`: 238/238, 23 файла, включая 78 серверных тестов. `npm run test:server`, `npm run build` и `git diff --check` успешны. Повтор migrate/seed после перезапуска сохранил данные; собранный API schemaVersion=8, preview-клиент прочитал прежние 12 участников, 25 очков/120 XP demo_01 и принятое через UI приглашение.
- Фактический браузер, отдельная временная БД: гостевой пустой рейтинг, учебный набор/ничьи/пагинация/личная позиция demo_12 со второй страницы, публичные профили, фильтры/reload/back/forward. Два входа, обзор/история/профиль/программы/соревнования, завершённое испытание, принятое задание дуэли; новое приглашение demo_12 принято demo_01 и сохранилось после reload. Программа squat→pushup 1×1+1×1 действительно пройдена **в синтетическом демо** через UI до сохранённого итога без XP. Начисления camera в API-тестах и seed вымышленные. Основная пользовательская БД не использовалась.
- Широкая/узкая компоновки измерены как 1440/390 CSS px, горизонтального переполнения основных страниц нет. Искусственный отказ чтения журнала только временной БД показал ошибку рейтинга; восстановление и «Повторить» вернули прежние очки. После восстановления integrity_check=ok, последняя чистая навигация без console warn/error. Shiro fix и конкретные исправления: [обзор UI](../ui-review.md).
- Реальная камера/видео, внешняя точность распознавания и античит не проверены. Видео и точки остаются в браузере. Импорт старых программ и восстановление обычной незавершённой программы после reload не добавлены; дуэль восстанавливает только подтверждённые записанные шаги. Локальная платформа не публиковалась и не деплоилась.
