# XP, достижения, испытания и дуэли — этапы 5–7

Правила `progression-v1` определены на сервере в `server/progression.ts`, расширение испытаний `challenges-v1` — в `server/challenges.ts` и `server/challengeSeed.ts`. Общие DTO и тексты причин — `shared/progression.ts` и `shared/challenges.ts`. Это учебный учёт структурированных результатов: сервер проверяет владельца, связь с запуском, снимок цели и согласованность результата, но не доказывает подлинность движений и точность компьютерного зрения. Видео и координаты остаются в браузере.

## Политика

- **20 XP за задание**, независимо от числа шагов, подходов, скорости и повторов сверх цели. Программа — одно задание, дети отдельно не награждаются.
- **60 XP за тренировки в день**, общая проектная зона **Europe/Kyiv**. Дневной остаток ограничивает награду: `min(20, max(0, 60 − workout XP за этот день))`. Дата определяется временем первого успешного серверного завершения, а не датой/длительностью результата клиента. Успешная повторная отправка на следующий день не переносит награду и не создаёт новое событие. Этап 6 добавляет отдельную версию политики бонусов испытаний ниже.
- Начало — уровень 1, XP 0. `level = floor(totalXp / 100) + 1`, `levelXp = totalXp % 100`, до следующего уровня `100 − levelXp`. XP суммируется только по журналу с `currency='xp'`.
- Только новый серверный запуск аккаунта с `reward_rules_version='progression-v1'`, `mode='camera'`, проверенным снимком и полностью выполненной целью. В каждом предусмотренном подходе должны быть `ended='completed'` и `result.reps >= goal.reps`. Для программы дополнительно `ended='completed'`, все шаги и их цели. Ручной конец подхода с недобором, отсутствие подходов, прерванная программа не подходят. Полные повторы, неполные/неоценённые попытки и замечания остаются раздельными; замечания не отменяют полный повтор и не являются общим «процентом безопасности».
- Гость, demo, video, исторический импорт и старые запуски не дают XP и прогресс достижений. Миграция не делает backfill: NULL версии у прежних запусков сохраняется. Повтор старого результата, импорт, повтор миграций/каталогового наполнения не создают наград.
- После дневного предела полностью выполненные допустимые задания продолжают давать **факты активности и прогресс значков**. Число зачтённых повторов для достижений ограничено целью каждого подхода; дополнительные повторы не ускоряют прогресс. Частично выполненные задания в эти показатели не входят.

## БД и согласованность

Миграция `005_progression.sql` добавляет nullable `workout_runs.reward_rules_version` без изменения старых миграций/данных:

- `progression_events`: result_id (PK/FK), user_id, reason, eligible, reps в пределах цели, exercises_json, event_at UTC, project_day, rules_version. Фиксирует решение и для исключённых новых результатов; импорт не создаёт событие.
- `reward_ledger`: пользователь, `currency: xp | competition_points`, `source_type: workout | challenge | duel`, source_id, amount > 0, event_at UTC, project_day, rules_version. Уникальность `(user_id,currency,source_type,source_id)`. На этапе 5 записывается только workout/xp, source_id — серверный **ID результата**, не run ID и не ID ребёнка.
- `user_achievements`: PK(user_id,achievement_id), result_id FK на событие, earned_at UTC, rules_version. Привязка хранит, какое завершение впервые выдало значок.

Сохранение результата, события, XP, значков выполняется в одной **BEGIN IMMEDIATE** транзакции SQLite. Сначала под блокировкой проверяется существующий результат. Точное повторение возвращает прежние данные (200), первый результат — 201, изменение — 409. Ошибка любого INSERT откатывает всё; можно безопасно повторить. Уникальные ограничения сохраняют однократность и при нескольких соединениях. Изменение/удаление записей журналов и достижений запрещено SQL-триггерами; архивирование результата меняет только archived_at.

Архив скрывает запись из списка истории, последних тренировок и прежних сводных показателей истории профиля. **Накопленный XP, значки, активность и статистика допустимых заданий остаются**: скрытие не отменяет произошедшего события. Прямые детали владельцу доступны. Новый запуск использует текущую доступную программу, завершение — ранее принятый снимок; изменение/архив шаблона не меняет награду.

## API и UI

- `POST /api/runs` сохраняет версию правил сервером. Клиент не передаёт версию, время начисления, XP или очки.
- `POST /api/runs/:id/complete` — единственный публичный путь начисления на этапе 5. Ответ `{result}` дополнен `result.reward`: `{reason,xp,earnedAt,achievements:string[]}`. earnedAt — время решения, включая исключённый новый результат; у старого/импорта null. achievements — названия значков, впервые выданных этим результатом. При повторе возвращается тот же receipt, он не означает новую выдачу.
- `GET /api/history` и `/api/history/:id` возвращают тот же receipt. Причины: awarded, daily_limit, demo, video, incomplete, legacy, import. Тексты UI объясняют каждую; гость видит отдельное объяснение без серверной награды.
- `GET /api/me/progression` → `{progression}`: xp, level, levelXp, nextLevelXp (100), todayXp, dailyLimit, workoutXp, timeZone, stats `{workouts,reps,days,exercises}`, activity (7 календарных дат по возрастанию, включая сегодня, `{day:'YYYY-MM-DD',workouts}`), achievements `{id,title,description,target,progress,earnedAt,reward}`. Никаких награждающих записей при GET нет.
- `GET /api/me/overview` → `{progression,recent:AccountResult[]}` (до 3 последних нескрытых результатов по серверному времени). Избранное использует существующий `/api/me/favorites`.
- `/overview` — персональная страница после входа/регистрации: уровень, XP, активность, последние результаты, избранное, достижения и CTA тренировки. `/profile` сохраняет редактор аватара/никнейма и показатели истории, добавляет уровень и коллекцию. Нужен вход; приватные данные определяются сессией, query userId запрещён, ожидаемый аккаунт проверяется `x-playfit-user`.
- Есть загрузка/пустые состояния/ошибка с повтором. Награда отображается только после подтверждения сохранения. Блокирующих анимаций нет; существующий reduced-motion сохраняется. Незавершённые запуски после reload не восстанавливаются, UI это не обещает.

## Контракт для этапов 6–8

`appendReward(db, RewardEvent)` — внутренний серверный интерфейс: `{userId,currency,sourceType,sourceId,amount,eventAt,rulesVersion}`. Требует активную транзакцию, положительное целое amount; точный повтор источника не вставляет строку, конфликт величины/версии бросает ошибку. Вызывать в immediate-транзакции завершения соответствующего **проверенного сервером** события; функция сама не проверяет чужое владение, снимок, дедлайн или выполнение задания и не заменяет эти проверки. Публичного API «начислить XP/очки» нет.

Испытания этапа 6 хранят собственный снимок принятого задания и новые связанные камерные runs: [контракт и API](challenges.md). Этап 7 добавляет [дуэли с отдельным принятым контекстом](duels.md). Не выдавать повторно workout XP за дочерние шаги. Даты/дедлайны — серверное UTC, дни — общая `projectDay`, недели понедельник–воскресенье. Рейтинг и изоляция учебных данных реализованы на этапе 8: [правила и API](demo.md).

## Бонусы испытаний — challenges-v1 (этап 6)

Это явное расширение политики этапа 5: **предел 60 XP относится к наградам `source_type=workout`; фиксированные бонусы `source_type=challenge` начисляются сверх него**. Бонусы не уменьшают остаток workout XP. Общий XP/уровень суммирует все XP журнала; `todayXp` отражает только workout XP для дневного предела, `challengeXp` — накопленные бонусы испытаний. `competitionPoints` суммирует отдельную валюту и не повышает уровень.

| Учебное испытание | Цель | Бонус XP | Соревновательные очки |
| --- | --- | --- | --- |
| Два движения — одна цель | 1 полная программа приседания → отжимания | 30 | 10 |
| Опора на себя | 1 полная программа отжиманий | 30 | 10 |
| Три встречи с движением | 3 полные тренировки по принятому плану приседаний | 50 | 20 |

Награда фиксируется при вступлении, выдаётся **один раз за participation ID** и не зависит от скорости, повторов сверх цели или числа повторных запросов. Участие уникально по пользователю и постоянному ID испытания, включая новые редакции. Допустимый внутренний авторинг ограничивает бонус каждой валюты целыми 1–100, а цель — 1–10 событий (`program` всегда 1). В текущем недельном наполнении максимум бонусов — **110 XP и 40 очков за три задания**. Отдельного суточного предела бонусов нет; командой seed нельзя получить повторный бонус за тот же период. События прошлой недели не переносятся в новую.

Обычные 20 workout XP (с пределом 60) и отдельные 30/50 XP испытания — разные строки журнала. Каждая программа даёт одну обычную награду; дочерние шаги не дают дополнительных строк. Последняя тренировка испытания может дать 0 workout XP из-за дневного предела и всё равно завершить испытание/выдать его фиксированный бонус. Значок первого испытания использует `user_achievements` и не даёт дополнительных XP или очков.

Прогресс — допустимые уникальные новые камерные события только из явно связанного запуска, после вступления, в принятой программе и **до серверного дедлайна**. Один результат учитывается только в выбранном испытании, без автоматического зачёта в других. Поздний первый результат сохраняется как тренировка, но получает `expired` и 0 бонуса/прогресса испытания; повтор своевременно сохранённого результата сохраняет старый receipt. Ошибка транзакции откатывает результат, все награды, значки и прогресс вместе.

## Асинхронные дуэли — duels-v1 (этап 7)

Формула и исходы зафиксированы перед внедрением: Дуэль — два разных аккаунта, один снимок каталожной программы и одна камерная сессия на участника. Создатель задаёт допустимые параметры шагов и срок 1–168 часов; сервер фиксирует абсолютный endsAt. Код открывает только приглашение: план, формулу, срок и публичный никнейм создателя, без истории и результатов. После принятия план не меняется. Отмена доступна создателю только до принятия.

Балл — целое 0–10000 (UI делит на 100, показывает процент достигнутой цели с двумя знаками): для каждого шага суммируем min(полные оценённые повторы подхода, цель повторов) по предусмотренным подходам; делим на (число подходов × цель повторов); берём среднее долей всех шагов; умножаем на 10000 и округляем Math.round один раз. Отсутствующие шаги/подходы дают 0. Каждый шаг весит одинаково. Неполные и неоценённые попытки не дают вклад, замечания хранятся отдельно. Скорость и дополнительные повторы не дают преимущества. Сравниваем округлённые целые; равенство, включая две полные цели и два нуля, — ничья.

Автомат: invited → accepted → waiting (первая окончательная отправка) → completed (вторая). invited → cancelled по отмене; invited/accepted/waiting → expired по сроку, кроме одной положительной отправки: тогда completed с победой из-за отсутствия отправки соперника. При двух отправках сравниваются баллы, в том числе нули. При отсутствии обеих или единственной нулевой отправке — expired, без победителя и наград. Начать/принять/впервые отправить можно только при now < endsAt. Записанный черновик не равен окончательной отправке; по сроку сам не отправляется. Окончательно отправленный результат изменить нельзя. Точные повторы отправки возвращают прежний итог даже после срока.

Сессия создаётся сервером после принятия, уникальна для участника. Черновик — отдельная запись с последовательной ревизией; точный повтор ревизии идемпотентен, устаревшее изменение отклоняется. Сохраняются завершённые шаги и итог остановки; после reload доступны серверный статус и записанные шаги. Незаписанные кадры/текущий подход не восстанавливаются. Окончательная отправка использует сохранённый черновик через общий /runs/:id/complete. Сервер проверяет владельца, camera, контекст дуэли, точный снимок, порядок и согласованность шагов, время и единственность. Demo/video/import/обычная история не могут быть привязаны к дуэли.

В completed положительно набравший и отправивший участник получает один бонус: победа 30 XP/15 очков, ничья 20 XP/10 очков, поражение 10 XP/5 очков. Нулевой/отсутствующий результат не даёт бонуса и значка. «Первая дуэль» выдаётся один раз за положительный результат в завершённой дуэли, без дополнительных валют. Бонус duels-v1 идёт через appendReward, sourceType=duel, sourceId=duel.id, отдельно для каждого пользователя/валюты, сверх дневного workout-предела. Полностью выполненная программа также получает обычные workout XP при окончательной отправке; за черновик XP нет. Нулевой результат может дать ничью, но не награду. Учебная система не доказывает подлинность клиентского движения и не реализует античит.

duel_events фиксирует исход каждого участника и единый eventAt для рейтинга этапа 8: при двух своевременных отправках — серверное время второй отправки; при завершении по сроку — сам endsAt, независимо от времени первого чтения. На чтении/действии финализация выполняется в BEGIN IMMEDIATE, без scheduler. Результат, progression и возможная финализация/бонусы/значки записываются атомарно. Повторная финализация, архив истории, изменение/архив исходной программы не меняют снимки, события и награды.

## Рейтинг и учебный режим — этап 8

Рейтинг суммирует только competition_points из журнала challenge/duel. Общий зачёт включает всю историю начислений; недельный — event_at в интервале projectWeek [понедельник 00:00, следующий понедельник 00:00) по Europe/Kyiv. Равные суммы дают общее место с пропуском следующего: 1,2,2,4. Вторичный порядок ID не участвует в ранге. Личное место вычисляется до LIMIT/OFFSET. XP определяет только показываемый уровень.

Вымышленные события платформы допускаются только в отдельном учебном наборе demo_users: принадлежность аккаунта неизменяема, результаты и награды связаны с ним. Явный seed использует общие функции завершения и формулы, создаёт журнал, а не готовый баланс. Обычный рейтинг исключает demo_users, учебный включает только их; соревнования и баннеры также учитывают режим. Это отличается от mode=demo в тренировке: такой результат по-прежнему не даёт XP, значков или очков. Подробности, API и логины только специальных учебных аккаунтов: [demo.md](demo.md).
